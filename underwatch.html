The pipeline

The five stages, in detail

  1. 1 · An action happens on the endpointA file is copied to USB, a command is run, a USB is plugged in, or someone SSHes into another server.
  2. 2 · A capture script notices it — using native tools onlyLinux: auditd + fanotify. Windows: the event log + a keystroke reader. macOS: the unified log + the script recorder. Nothing is installed.
  3. 3 · It becomes one structured eventA single JSON line written to a local log — e.g. {"type":"file_upload","name":"report.xlsx","dest":"drive.google.com"}.
  4. 4 · The detection engine matches a ruleThe Wazuh agent forwards the event; on the server ~90 rules decide if it's risky.
  5. 5 · An alert appears"Sensitive file uploaded to drive.google.com" lands on the dashboard — with the user, file, and time.

The hard part

Capturing commands typed on another server

When someone runs ssh admin@host and types commands there, we still capture every command — by wrapping ssh on the source machine and recording the whole session with the native script tool. It works even if the remote server has no monitoring at all.

$ ssh admin@host
admin@host:~$ whoami → remote command detected
admin@host:~$ sudo su → remote command detected
root@host:~# cat /etc/passwd → remote command (as root)
root@host:~# rm -rf /var/log/* → ⚠ DANGEROUS remote command

Because the recording captures the prompt changing from admin@ to root@, it even shows whether each command ran as a normal user or as root.
